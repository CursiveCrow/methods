## Native presentation distinctions and direct corrections

1. BG2009 uses H as postprocessor and K as preprocessor. BDP2010 uses
   K as postprocessor and H as preprocessor. Both actual formulas are
   stated separately before use, with no fictional notation namespace.
2. Native2009LPO outputs0 if some coordinate equals0 and1 otherwise.
   The all-zero characteristic test is a different literal map. The
   reader prints both and gives two strong input translations.
3. Native2009LLPO has one Baire input with at most one nonzero coordinate,
   and answers0/1. Native2010LLPO=MLPO2 instead has an encoded tuple,
   at least one zero-stream component, and answers1/2. Both definitions,
   typed roles and the finite-choice bridge are retained. Parity arguments
   explicitly use the2009presentation, without suppressing the other.
4. BG2009Proposition6.5p21 prints an LLPO input-recovery row with a1
   at every odd position when p(k)=m, or every even position otherwise.
   This violates its Definition6.1 single-marker domain. Source pixels
   confirm the formula. The active proof replaces it with exactly one
   marker, at position1 or0 respectively, then zeros. Recovery and
   cylindrification are fully proved with the corrected valid inputs.
5. BG2009Lemma8.9p32's reverse real comparison translator puts an even
   marker for x<0 and an odd marker for x>0, yielding the opposite
   permitted answers under its own definitions. Pixels confirm this.
   The active proof puts an odd marker for negative x and an even marker
   for positive x, with a full strict-sign semidecision and zero case.
6. BDP's native limDelta is a discrete-topology limit of whole Baire
   streams, not a scalar natural limit. The source ordinary equivalence
   uses original-input recovery. The new scalar stage/value construction
   has a stronger interface, and the explicit noncomputable-stream
   counterexample proves the whole-stream reverse strong reduction fails.
7. Native partial marker subseteq, multivalued rightrightarrows,
   A_-(X),psi_-^X, upright W/sW subscripts and sans-serif choice/omniscience
   operators are preserved. Source code fixes their actual glyph roles;
   body/annex/intakes use the rendered syntax rather than ASCII aliases.

Cantor exterior words have an explicit plus-one/padding encoding.
The source's potentially empty enumeration and the host code therefore
have a genuine uniform interface, not an unexplained identification.
Strong proof postprocessors use only the answer; ordinary proofs identify
where the original input is needed. Coordinate permutation does not
