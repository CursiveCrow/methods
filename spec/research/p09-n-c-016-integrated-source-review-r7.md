# Must-fix findings

## 1. Lines 1019--1025 omit the infinite-path-set hypothesis from the displayed \(R\)-generability equivalence

The manuscript first permits \(X\) to contain nonempty finite or infinite paths.  It later writes, without a displayed domain qualification,

\[
 R\text{-generable}
 \quad\Longleftrightarrow\quad
 \text{suffix closed, fusion closed, limit closed, and state complete}.
\]

The controlling note states the cited characterization specifically **for sets of infinite paths** (`p09-emerson-halpern-1986-source-note.md`, lines 166--169).  Adding state completeness is a correct handbook repair when the generating relation is total on all of \(S\): totality forces an infinite path from each state, while the three closure properties plus state completeness give the converse construction.  But state completeness does not replace the missing hypothesis that \(X\) consists only of infinite paths.

Without that hypothesis the displayed equivalence is false.  For example, on a one-state universe, take \(X\) to contain every nonempty finite constant path as well as the infinite constant path.  It is suffix closed, fusion closed, limit closed, and state complete, but it is not a set consisting exactly of the infinite paths generated by a total relation.

Minimal repair: introduce the display with an explicit domain, for example:

> For \(X\subseteq S^\omega\), and with the generating relation total on all of \(S\), the reader-facing exact form is ...

Keep the state-completeness conjunct and the statement that it is a handbook qualification of the source's three-closure wording.

## 2. Line 520 overstates the variable vector of the Queille--Sifakis IPN

The manuscript calls \(\mathbf X\) a vector “of all program variables.”  The controlling source note defines only a vector of variables and then records that the translator type-checks and **deletes internal variables of non-specified types** (`p09-queille-sifakis-1982-source-note.md`, lines 203--215).  Consequently the IPN vector cannot unqualifiedly be the vector of all variables in the input description program.

Minimal repair: replace “of all program variables” with “of the program variables retained by the translation,” or simply “of variables,” and state locally that internal variables of non-specified types are type-checked and deleted.  The guarded-command definition and all later uses of \(\mathbf X\) may remain unchanged.

## 3. Lines 1594--1598 guard the host method by nonemptiness but not by finiteness

The manuscript says:

> When \(S\ne\varnothing\), together with \(\mathcal K_0=(S,R_0,V_0)\), it supplies the exact typed input to Method~\ref{def:p09-ctl-labelling}.

The host method's signature at `handbook/parts/p09/logic-in-computer-science.tex`, lines 974--976, takes a **finite total transition structure** and a CTL formula.  Nonemptiness plus the source's no-terminal-state condition makes \(R_0\) total, but it does not make an arbitrary source state set finite.  The N-c-016 text itself supplies the missing condition correctly a few lines later: only when the source transition system is finite is \(\mathcal K_0\) a finite total structure of the host method's type.

Minimal repair: change the first input claim to:

> When \(S\ne\varnothing\) and the source transition system is finite, together with \(\mathcal K_0=(S,R_0,V_0)\), it supplies the exact typed input to Method~\ref{def:p09-ctl-labelling}.

Alternatively, delete the early “exact typed input” sentence and let the correctly qualified case split at lines 1606--1611 establish method eligibility.  Do not add finiteness to the semantic equivalence at lines 1679--1687: host satisfaction on a nonempty total structure is meaningful even when the structure is infinite.  The actual method-result claim at line 1688 is already correctly restricted to finite nonempty \(S\).
